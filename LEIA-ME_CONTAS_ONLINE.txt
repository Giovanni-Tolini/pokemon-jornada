POKÉMON JORNADA — CONTAS ONLINE E BATALHAS PvP (ETAPAS 1, 2 e 3)
=========================================

O QUE VOCÊ PRECISA FAZER NO SUPABASE
----------------------------------------------------
1. Abra https://supabase.com/dashboard e entre no projeto jdslesmypytmuvesddbh.
2. Menu "SQL Editor" -> "New query".
3. Abra o arquivo supabase/setup_pokemon_jornada.sql, copie TODO o conteúdo, cole no editor e clique em RUN.
   Deve aparecer "Success. No rows returned". Pode executar de novo sem problema (não apaga contas).
4. Confira em "Table Editor": devem existir pj_players, pj_sessions, pj_saves, pj_save_backups e pj_attempts,
   todas com o selo "RLS enabled".
5. Não é preciso mexer em Authentication: este sistema NÃO usa o Supabase Auth (não precisa de e-mail nem
   de confirmação de e-mail).
6. Confirme em Project Settings -> API (ou "Data API") que o schema "public" está exposto (é o padrão).

COMO TESTAR
-----------
- Abra index_evolucao_corrigido.html (de preferência com a extensão Live Server do VS Code).
- Crie uma conta. No Supabase, em Table Editor -> pj_players, a conta aparece com password_hash começando
  em $2a$ (senha criptografada com bcrypt; a senha em si nunca é gravada).
- Se aparecer "O servidor ainda não foi configurado", o SQL do passo 3 não foi executado (ou o schema não
  foi recarregado: rode `notify pgrst, 'reload schema';` no SQL Editor).

SEGURANÇA
---------
- Só a chave publishable está no navegador (account/config.js). Nunca coloque service_role/secret ali.
- As tabelas têm RLS ligado e nenhuma policy: a chave publishable NÃO lê nem grava tabelas diretamente.
  Tudo passa por funções (pj_register, pj_login, pj_validate_session, pj_logout, pj_get_save, pj_put_save)
  que validam tudo no servidor.
- Senhas com bcrypt. Sessões: token aleatório de 256 bits; só o hash SHA-256 fica no banco; validade de 90 dias.
- Bloqueio de 10 min após 8 senhas erradas para o mesmo nome; limite de 10 cadastros/hora por IP.

COMO O SAVE NA NUVEM FUNCIONA (ETAPA 2)
---------------------------------------
- O jogo continua salvando no navegador; depois de ~2,5 s o progresso sobe para a sua conta. Indicador no cabeçalho:
  "Salvo na nuvem", "Pendente", "Offline", "Sync pausada" ou "Decisão pendente".
- Computador novo: entrar com a mesma conta baixa o progresso da nuvem e o jogo abre exatamente de onde parou.
- Save antigo do navegador + conta nova: pergunta se quer VINCULAR (ou começar do zero, mantendo o save antigo como cópia).
- Save local diferente do da nuvem: tela "Qual progresso você quer manter?". Se escolher o do navegador, a versão da
  nuvem é copiada para backup no servidor (tabela pj_save_backups, 5 mais recentes). Se escolher a da nuvem, o save
  local fica guardado como cópia no navegador (chave pj_local_backups_v1, 3 mais recentes).
- "Decidir depois": o jogo funciona normalmente, nada é enviado, e "Sincronizar agora" (Perfil) reabre a decisão.
- Duas contas no mesmo navegador: o save de cada uma é guardado separado; uma não enxerga a outra.
- Se o save local e o da nuvem forem idênticos, a vinculação é automática (sem perguntas).
- "Apagar progresso" e "Importar save" (já existentes no jogo) agora guardam antes uma cópia local de segurança.

IMPORTANTE — ATUALIZAÇÃO DA ETAPA 3 (BATALHAS PvP)
--------------------------------------------------
Se você já configurou as contas online anteriormente, execute novamente TODO o arquivo
supabase/setup_pokemon_jornada.sql no SQL Editor. A atualização cria a arena PvP e substitui
a função de aceitar desafio para iniciar uma partida automaticamente. Ela não apaga contas nem saves.

COMO FUNCIONA A BATALHA ENTRE JOGADORES
---------------------------------------
- Ao aceitar um convite, o servidor cria uma partida usando cópias dos times salvos dos dois treinadores.
- Cada treinador escolhe um movimento ou troca de Pokémon por turno.
- A arena sincroniza as jogadas automaticamente a cada poucos segundos; ambos precisam estar online.
- Não há captura, itens ou alteração do HP do time principal: o combate usa cópias do time.
- Ao terminar, vitórias, vitórias contra treinadores e derrotas são atualizadas no save online.
- A aba “Batalha PvP” fica disponível no menu da lateral.
- Se o jogador não tiver ao menos um Pokémon no time salvo na nuvem, não poderá iniciar/aceitar a partida.


LIMITAÇÕES CONHECIDAS
---------------------
- Não há recuperação de senha (não existe e-mail na conta). Esqueceu a senha = conta nova (ou redefinição
  manual por você no SQL Editor).
- Não existe tela no jogo para restaurar os backups do servidor; eles ficam na tabela pj_save_backups
  (restauração manual pelo SQL Editor, se um dia precisar).
- "Apagar progresso" apaga só o save local; a nuvem só muda quando você começa um novo jogo e ele é salvo.
  Se recarregar antes disso, o progresso volta da nuvem.
- Dois computadores jogando ao mesmo tempo na mesma conta: vale o primeiro a salvar; o outro recebe a tela de escolha.
- Cada envio manda o save inteiro (algumas centenas de KB no máximo). Para muitos jogadores simultâneos, o plano
  gratuito do Supabase pode ficar apertado.
- Nome com acento: a comparação sem diferenciar maiúsculas depende do idioma (locale) do banco.
- O bloqueio por tentativas é por nome: alguém pode travar o login de um nome por 10 min de propósito.
- Sair sem internet encerra a sessão só no navegador; o servidor é avisado quando a conexão voltar
  (ou a sessão expira em 90 dias).
- Testado em Postgres 16 local + navegador Chromium, com o backend do Supabase simulado por chamadas diretas às
  mesmas funções SQL. Não foi testado no seu projeto Supabase real nem em Firefox/Safari.
